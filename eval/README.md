# 检索对比：v0.6 的 `recall` 和节点树的 `search`

同一批记忆、同一个语义模型、同一批问题，分别问 v0.6 的检索和节点树的检索，比较答案有没有出现在返回里。

## 怎么跑

```
recallport --data <v0.6 记忆库的副本> --model <model 目录> --tree-eval <问题.json> --keys <答案名.json>
```

结果写在问题文件旁边（`<问题>.report.md`）。**数据目录请用副本**，程序会打开它。

- `demo_seed.js` 通过 MCP 的 `remember` 造一份 143 条记忆的演示库（8 个项目、5 层汇总），并把「答案名 → 记忆编号」写进 `keys.json`；`demo_questions.json` 是 45 个有答案的问题加 4 个没有答案的问题。
- `needles_questions.json` / `needles_keys.json`：v0.4.1 压测时就有的「针」语料（34 条植入事实，每条 4 种问法：原文、同义改写、跨语言、错别字，另有 4 个无答案问题）。答案名对应记忆正文（`text:` 开头），需要用同一份 1k 压测库（未放进仓库）。

## 指标

- **命中@5**：答案在前 5 条里。**首位率**：第一条就是答案。**MRR**：首个答案名次的倒数的平均。
- **覆盖@1200**：按返回顺序读 1200 字之内读到的答案占比（AI 读得起多少字）。
- **误报**：没有答案的问题上，系统声称「有强匹配」。
- 三个系统：`v0.6 recall`；`树·纯混检`（所有层一起做关键词加语义检索，不带子节点）；`树·带子节点`（命中汇总时再带上最贴近问题的 3 个子节点）。`树·纯混检+语义下限` 是对照：给树加上 v0.6 的 0.80 相似度下限。

## 局限

问题是人（我）按语料写的，数据小；答案是少数几条记忆；基准不代表真实使用。
