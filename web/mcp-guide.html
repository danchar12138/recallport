工具手册

接入后，AI 可以使用下面 6 个工具，另有 brief（开始前先查）和 wrap_up（收尾记下收获）两个提示。服务端会在每次返回中附带提示，引导模型去重、关联、补实体和更正；是否主动调用仍取决于客户端和模型。

recall找线索read读原文remember留经历link建关联entity管实体health做体检
recall找以前的相关经历

用关键词、换一种说法，或按日期、按实体找记忆。不传 query 时按时间浏览。结果是线索，不是当前事实：每条命中都有 match（exact 字面包含、strong 高度相关、weak 弱相关、keyword 只按词匹配）和 relevance，一条强匹配都没有时 no_strong_match 为 true。被更正过的旧记忆会由更正它的新记忆代替出现（replaces 列出旧记录），旧文留在 trail 里，请一起判断，较新的记录不一定更准确。

query字符串 · 可选
要找的话题、原话或当前情境，最多 600 字符。例如 开机自启。
strategy枚举 · 默认 hybrid
hybrid 混合，默认推荐；lexical 关键词，适合路径或精确名称；semantic 语义，适合改写与同义词。
queries字符串数组 · 可选
同一件事的其他说法（同义词、另一种语言、报错原文），最多 5 条。每种说法都会检索，结果合并，被多种说法找到的更靠前。
history布尔 · 默认 false
设为 true 时，被更正过的旧记忆也作为独立命中列出。
entity字符串 · 可选
只看提及某个实体的记忆（传实体 ID）。
from / through日期字符串 · 可选
按发生时间筛选，含起止边界。支持 YYYY、YYYY-MM 或 YYYY-MM-DD。
limit整数 · 默认 8
最多返回多少条，取值 1–30。
{"query": "开机自启", "strategy": "hybrid", "limit": 5}
{{ copy_button("recall-example") }}

返回 memories（带 ID、时间、来源、提及的实体、match、relevance 和 trail）、mode、more、degraded、no_strong_match，以及提示下一步的 hint。

read展开某条记忆的完整内容

搜到线索后，用记录 ID 查看完整内容。传 ID，不传标题或搜索词。

id字符串 · 必填
从 recall 或 remember 的返回值取出的记忆 ID。
{"id": "替换成 recall 返回的 id"}
{{ copy_button("read-example") }}

返回 正文、情境、发生与写入时间、来源；双向的引用（带种类和原因）、实体、附件（含文件在本机的路径，可直接打开）、旧版本正文，以及更正轨迹。

remember追加一段值得留存的经历

保存决策、根因、有效的修复、失败的尝试、偏好、约束、变化和更正。只追加新记录，不改写旧记忆。账号、密码等私人信息按原文保存，不做分级，也不打码。

text字符串 · 必填
经历本身，用用户的语言，写得让没有上下文的人也能看懂。
context字符串 · 可选
背景，例如当时的设备、项目或限制。
occurred日期字符串 · 可选
经历发生的时间，不等于写入时间。只知道月份就填 2024-09，不知道就省略。
source字符串 · 默认 MCP
自报的记入来源，例如 Codex；不是已验证身份。
references数组 · 可选
引用的旧记忆。每项传 id，kind 取 relates（默认）、corrects（本条更正了它，旧的保留作历史）或 summarizes（本条汇总了它们，原文保留），可附 reason。
entities数组 · 可选
这条记忆讲的是什么。已有实体传 id 复用；新事物只传 name。同名时系统不会替你猜：会保存为「待确认」并在返回里给出候选，请用 link 选择；确实是另一个同名事物就加 new: true 和区分说明 hint；同名同说明视为同一个实体，重试不会重复创建。
attachments数组 · 可选
相关的文件。传绝对路径 path（小文件可传 data_base64，约 90 KB 以内），可附 name 和一句说明 caption（可被搜索）。默认复制入库；mode: reference 只记录位置，不进备份。
origin / request_id字符串 · 可选
origin 是同一次经历的稳定标识，用来折叠不同转述；request_id 只在写入超时后重试完全相同的请求时复用，避免重复写入。
{
  "text": "应用在用户登录后启动，而不是开机时启动。",
  "context": "Windows 后台工具，使用任务计划程序",
  "occurred": "2024-09",
  "source": "Codex",
  "entities": [{"name": "任务计划程序"}],
  "references": [{"id": "旧记忆的 id", "kind": "corrects", "reason": "旧方案不可行"}]
}
{{ copy_button("remember-example") }}

返回 新记录和稳定的 id，另有 related（内容相近的已有记忆）、entity_choices（待你选择的重名候选）和 hint。

link把记忆与记忆、实体、附件关联起来

三选一：to（另一条记忆）、entity（它讲的是什么，也用来确认「待确认」的名称）、attachment（附上文件）。重复调用只会更新；remove: true 只断开关联，不删除任何东西。

from字符串 · 必填
发起关联的记忆 ID，通常是较新的那条。
to + kind + reason可选
关联另一条记忆；kind 同上，更正旧结论时用 corrects。
entity对象 · 可选
{"name", "id", "aliases", "hint", "new"}：有 id 就复用，没有就按名称解析。
attachment对象 · 可选
{"path" | "data_base64" | "hash", "name", "caption", "mode"}；断开时传 hash。
{"from": "记忆 id", "entity": {"name": "主服务器", "id": "已有实体的 id"}}
{{ copy_button("link-example") }}

返回 关联结果；实体重名时给出 entity_choices。

entity实体目录：查找、查看、改名、合并

提交实体之前先查一下，复用正确的那个。名称不会被自动合并，是否同一个由 AI 判断，网页端也可以撤销合并。

action枚举 · 默认 search
search 按名称、别名或说明查找（不传 query 则列出提及最多的，并列出待确认的名称）；get 看一个实体及其随时间的记忆和同时出现的实体；update 改名、增删别名、设置区分说明；merge 把 id 并入 merge_into。
{"action": "search", "query": "服务器"}
{{ copy_button("entity-example") }}

返回 实体列表（含 ID、别名、说明、提及次数、最近出现）或单个实体的详情。

health记忆库体检：重复、没人处理的名称、更正链的问题

不需要参数。列出正文完全相同的记忆、同名却无法区分的实体、没有人处理的实体名称、没有关联任何实体的记忆、被两条以上不同更正的记忆（现状没有定论）、互相更正的循环、找不到文件的附件，以及缺向量的记忆。每一项附带几个起点和处理办法。会话开头的摘要在有事可整理时会提醒 AI 调用它。
