接入 AI

让你的 AI 客户端使用这份本地记忆。仅本机可访问，无需账号或令牌。

  1. 复制 MCP 地址

    在客户端里选择 Streamable HTTP 方式，粘贴下面的完整地址（含协议、端口和 /mcp）。

    {{ copy_button("endpoint") }}

  2. 添加到客户端

    选择你使用的客户端，把配置合并到对应文件中（已有配置时只加 recallport 这一项），然后重载或重启客户端。

    写入 ~/.codex/config.toml 
    [mcp_servers.recallport]
url = "{{ Base }}/mcp"
    {{ copy_button("codex-config") }}
    写入项目根目录的 .mcp.json 
    {
  "mcpServers": {
    "recallport": {
      "type": "http",
      "url": "{{ Base }}/mcp"
    }
  }
}
    {{ copy_button("claude-config") }}

  3. 让 AI 主动用起来 推荐

    服务端已内置使用指引，但有些客户端会忽略它。把下面这段加入客户端的规则文件（如 AGENTS.md、CLAUDE.md），模型就会在任务开始前主动查记忆，并在决策、踩坑、被纠正后主动记录、去重和关联。

    ## 长期记忆（RecallPort）
- 开始较大的任务、做技术选型或改动配置之前，先调用 recall 查找相关的过往经历；没找到就换个说法，或用 strategy=semantic 再试一次。
- 出现这些情况后，立刻调用 remember 记录，不必等我提醒：做出带理由的决定、找到根因、验证有效的修复、失败的尝试及原因、我的偏好或约束、被我纠正。
- 记录前先 recall：已有相同内容就不要重复；旧记忆过时或错误时，记一条更正，并在 references 里引用旧记忆。
- 相关的记忆用 link 关联起来。不要自动记录密码、密钥或令牌；我明确要求保存某个凭据值时，可以按原文记入。不要记录整段对话。
    {{ copy_button("agent-rules") }}

  4. 测试连接

    检查本页能否连上本机的 MCP 端点。这不能代替客户端自己的连接测试，但能先排除服务端问题。

    • 本机服务可访问
    • 完成 MCP 握手
    • 读取工具列表（recall、read、remember、link）

工具手册

接入后，AI 可以使用下面 4 个工具。服务端会在每次返回中附带提示，引导模型去重、关联和更正；是否主动调用仍取决于客户端和模型。

recall找线索read读原文remember留经历link建关联
recall找以前的相关经历

用关键词、换一种说法，或按日期找记忆。不传 query 时按时间浏览。结果是线索，不是当前事实。

query字符串 · 可选
要找的话题、原话或当前情境，最多 600 字符。例如 开机自启。
strategy枚举 · 默认 hybrid
hybrid 混合，默认推荐；lexical 关键词，适合路径或精确名称；semantic 语义，适合改写与同义词。索引异常时可能降级。
from / through日期字符串 · 可选
按发生时间筛选，含起止边界，可只填一端。支持 YYYY、YYYY-MM 或 YYYY-MM-DD。
limit整数 · 默认 8
最多返回多少条，取值 1–30。
{"query": "开机自启", "strategy": "hybrid", "limit": 5}
{{ copy_button("recall-example") }}

返回 hint 提示下一步怎么做；memories 是带 ID、时间及来源的片段；mode 是实际检索模式；more 表示这次结果已截断；degraded 表示已降级。

read展开某条记忆的原文

搜到线索后，用记录 ID 查看完整上下文和引用。传 ID，不传标题或搜索词。

id字符串 · 必填
从 recall 或 remember 的返回值取出的记忆 ID。
{"id": "替换成 recall 返回的 id"}
{{ copy_button("read-example") }}

返回 正文、情境、发生时间、写入时间、来源，以及引用和反向引用；hint 提醒记忆可能过时，错误时应记录更正而不是直接依赖。

remember追加一段值得留存的经历

只追加新记录，不改写旧记忆。不会自动收集凭据；你明确要求保存时可以记入原文。凭据会出现在 Web、MCP 返回和明文备份中。

text字符串 · 必填
经历本身，例如「应用在用户登录后启动，而不是开机时启动」。
context字符串 · 可选
让旧事易于理解的背景，例如当时的设备、项目或限制。
occurred日期字符串 · 可选
经历发生的时间，不等于写入时间。只知道月份就填 2024-09，不知道就省略。
source字符串 · 默认 MCP
自报的记入来源，例如 Codex；不是已验证身份。
origin字符串 · 可选
同一次经历的稳定标识，用来在检索时折叠不同转述。不要用整个项目或会话的 ID 代替。
request_id字符串 · 可选
写入超时后，重试完全相同的请求时复用原 ID，避免重复写入。新经历用新 ID。
references数组 · 可选
明确引用的旧记忆。每项传 id，可附 reason 解释为什么相关。
{
  "text": "应用在用户登录后启动，而不是开机时启动。",
  "context": "Windows 后台工具，使用任务计划程序",
  "occurred": "2024-09",
  "source": "Codex"
}
{{ copy_button("remember-example") }}

返回 新记录和稳定的 id，另有 related（内容相近的已有记忆）和 hint。模型据此判断是否重复，并用 link 建立关联或记录更正。

link把两条已有记忆关联起来

发现两段经历属于同一话题，或新记忆更正、延续了旧记忆时使用。重复调用只会更新说明。

from字符串 · 必填
发起引用的记忆 ID，通常是较新的那条。
to字符串 · 必填
被引用的旧记忆或相关记忆 ID。
reason字符串 · 推荐
为什么相关。更正旧结论时以「更正」开头，例如「更正：旧方案在企业策略机器上不可用」。
{"from": "新记忆的 id", "to": "旧记忆的 id", "reason": "更正：旧结论已过时"}
{{ copy_button("link-example") }}

返回 linked、from、to。关联会立即出现在 Web 的详情页和关系图里。
