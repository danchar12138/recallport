其他客户端

任何支持 MCP 的 HTTP 方式（Streamable HTTP）的客户端都能接入，地址同上，不需要认证。配置的字段名因客户端而异（常见的有 type / transport、url / serverUrl），以它自己的文档为准。

JSON（mcpServers 写法）

{
  "mcpServers": {
    "recallport": {
      "type": "http",
      "url": "{{ Url }}"
    }
  }
}

TOML（Codex 一类）

[mcp_servers.recallport]
url = "{{ Url }}"

工具手册

接入后，AI 能用到下面 9 个工具。整份手册可以复制给 AI（比如放进项目说明里）。

AI 怎么维护这棵树

  • 记忆是一棵树。第 0 层是 AI 从对话里提取的原子记忆，每条是一段完整的经历（发生了什么、为什么、结果）；更高的层是 AI 写的汇总，层数不限。
  • 写汇总：用 write，并在 adopt 里列出它概括的节点；这些节点就挂到新节点下面，新节点比它们高一层。汇总只是索引，细节要用 get 看它下面的节点。
  • 保养：maintain 自下而上地列出缺汇总的地方，分批给出——new 是需要新写一条汇总的一批节点，extend 是可以补进已有汇总的节点——还有已经过期的汇总（下面有比它更新的节点）。AI 补写或改写之后，核对过仍然正确的汇总用 update 加 touch 刷新。
  • 不会丢：每次改动都留在节点的历史里（get 加 history 可以看）；delete 只是进回收站，放满一个月前随时能 restore。

search找记忆

什么时候用：开始较大的任务、做技术选型、改配置之前，先查有没有相关的过往经历；没找到就换几种说法再查。

query字符串
要找的话题、原话或当前情境。
queries字符串数组
同一件事的其他说法（同义词、另一种语言、原始报错）。每种说法都会检索，结果合并。
scope节点编号
只在这个节点和它下面的所有节点里找。
min_layer / max_layer整数
只要这个层范围内的节点：0 是原子记忆，更高的层是汇总。
tag字符串
只要带这个标签的节点。
from / through日期
按“事情发生的日期”（occurred）筛选，含两端，格式 YYYY-MM-DD，可以只写前几位。没有日期的节点不会被排除。
limit整数
最多返回几条。
expand整数
命中的是汇总时，顺带带出它下面最相关的几个节点。

返回命中的节点：编号、层、正文（太长会截断，要全文用 get）、标签、发生日期、与问题的相关度；汇总命中时带上它下面最相关的节点，每个命中还带着它上面各层汇总的路径。没有真正相关的内容时会明说，命中只是线索。

{"query": "备份策略", "queries": ["backup schedule", "每天几点备份"], "max_layer": 1, "limit": 5}

get读一个节点的全部

什么时候用：搜到线索后看完整内容；顺着汇总往下找细节；改它之前先读一遍，拿到当前版本号。

id节点编号 · 必填
从 search、write 等的返回里取。
history布尔
为 true 时附上这个节点每一版的正文、改动人和时间。

返回完整正文、版本号、标签、发生日期、所在的层、从最上面到它的路径、它的子节点、引用和被引用、来源、附件（含文件在本机的路径）。

{"id": "替换成节点编号", "history": true}

write写入新节点

什么时候用：做出带理由的决定、找到根因、验证有效的修复、失败的尝试、用户的偏好或约束、情况变化之后；也用来写汇总。先 search，已有同样的内容就改它，别重复写。

content字符串 · 必填
正文。一段完整的经历，用用户的语言写，让没有上下文的人也看得懂。
parent节点编号
把新节点直接放在这个节点下面。不填就暂时不属于任何汇总。
adopt节点编号数组
写汇总用：把这些已有节点收到新节点下面，新节点成为它们的父节点。
tags字符串数组
标签，用来按项目、设备、人等筛选。
refs节点编号数组
相关、但不是上下级的其他节点。
sources字符串数组
信息从哪来：文件名、网址、哪次对话。
occurred日期
事情发生的日期，YYYY-MM-DD，可以只写年或年月。
attachments对象数组
要归档的文件。每项：path（本机绝对路径）或 data_base64（内联内容，约 96 KB 以内，更大的请用 path）；name 文件名；caption 一句说明（说明不会被搜索，重要的信息写进正文）；reference 为 true 时只记住文件的位置、不复制进记忆库（只对 path 有效）。

返回写好的节点，内容和 get 一样（含新节点的编号和所在的层）。

{"content": "家庭服务器的备份改成每天凌晨三点跑，因为白天会占满上行带宽。", "tags": ["家庭服务器"], "occurred": "2026-11-22"}
{"content": "家庭服务器的备份策略：每天凌晨三点，保留七份。", "adopt": ["节点编号 1", "节点编号 2"]}

update改写或刷新节点

什么时候用：情况变了就改写那条旧节点，旧的内容会留在历史里，不要让两条互相矛盾的节点同时存在；汇总核对过仍然正确时，用 touch 刷新。

id节点编号 · 必填
要改的节点。
version整数
你读到的版本号。节点在那之后被别人改过，这次更新会被拒绝，免得盖掉别人的修改；不填则按最新版本。
content字符串
新的正文。不填表示不改正文。
tags / refs / sources数组
整个换成新的列表（不是追加）。不填表示不动。
occurred日期
新的发生日期。
add_attachments对象数组
要新增的附件，写法同 write 的 attachments。
remove_attachments数组
要摘掉的附件（用 get 返回的附件标识）。
touch布尔
为 true 表示“核对过，仍然正确”：不改内容，只刷新这个节点的更新时间，它之后不再被当作过期。

返回更新后的节点，内容和 get 一样。

{"id": "节点编号", "version": 2, "content": "备份改成每天凌晨四点，保留十四份。"}

move调整位置

什么时候用：整理这棵树，把节点挪到更合适的汇总下面。

ids节点编号数组 · 必填
要移动的节点，它们下面的子节点跟着走。
to节点编号
移到哪个节点下面；不填就移到最上层。

返回移动的结果；不合法的移动（比如把节点放进它自己的子树里）会被拒绝并说明原因。

{"ids": ["节点编号 1", "节点编号 2"], "to": "汇总的节点编号"}

delete删除节点（进回收站）

什么时候用：重复的、错误的、已经没有意义的节点。不是永久删除：回收站里放满一个月才会被清掉，期间可以 restore。

id节点编号 · 必填
要删除的节点。它下面的子节点不会被删，而是上移，挂到它原来的父节点下面。
version整数
你读到的版本号，用法同 update。
reason字符串
为什么删，记在历史里。

返回删除的结果，包括有几个子节点上移了。

{"id": "节点编号", "reason": "和另一条重复"}

restore从回收站取回

什么时候用：删错了，或者情况又变回来了。

id节点编号 · 必填
回收站里的节点（用 trash 查）。

返回取回后的节点，内容和 get 一样。

{"id": "节点编号"}

trash看回收站

什么时候用：找被删掉的节点，决定要不要 restore。

limit整数
最多列出几个。

返回回收站里的节点（编号、正文的第一行、删除时间和原因）。

{"limit": 20}

maintain树的保养清单

什么时候用：一段时间写了不少新记忆之后，或者在较长的任务收尾时，时不时调用一次。它只给清单，不改任何东西。

（没有参数）
传空对象 {}。

返回每一层的节点数，以及已经有多少挂在汇总下面；过期的汇总和下面比它更新的节点；自下而上的下一批缺口——new 是需要新写一条汇总的一批节点，extend 是可以补进已有汇总的节点。一轮处理完再调用，会给出下一批或更高一层。

遇到问题

  • 客户端不调用工具。接入之后要重启客户端（Claude Code 要新开一个会话）才会读到新配置。点上面的“验证连接”确认服务和 9 个工具都正常；再写入“使用规则”，AI 会更主动地查和记。仍然不用的话，直接对它说“先用 RecallPort 查一下”。
  • 验证连接失败或连不上。确认 RecallPort 还在运行（系统托盘里有它的图标），并且客户端配置里的地址和上面的 MCP 地址一致。
  • 端口被占用。默认端口 3765。被其他程序占用时，RecallPort 会改用附近的端口，MCP 地址也就变了：再点一次“一键接入”（卡片提示“地址不同”时选“替换为当前地址”）。想固定端口，可以用 --listen 127.0.0.1:端口 启动。
  • 想还原客户端的配置。每次改动前，RecallPort 都会在配置文件旁边留一份 .recallport-时间.bak 备份，直接换回去就行。
