# 检索评测

8 个不同的人（中文开发者、英文工程师、留学生、自由职业设计师、家庭用户、博士生、创业者、爱好者）各一年的记忆库和之后会被问到的问题，用来评估和调整搜索排序。

- `corpus_P1.json` … `corpus_P8.json`：每个文件约 220 条记忆（含改口、AI 没发现旧记忆而追加的新版本、近似干扰、汇总、删除）和约 90 道问题。问题分 12 类：直接问、换说法、模糊、关键词、跨语言、带时间、问「现在」、问「以前」、概览、多跳、近似干扰、库里没有（`absent`）。每道题带若干种说法（`qs`）、答案所在节点（`gold`）、容易混淆的旧版本或另一个实例（`stale`）。
- `SPEC.md`：这批数据的生成规格。
- `study.py`、`compare.py`：在导出的向量和词项上离线重放排序，几秒钟就能比较一种新做法。

## 用法

先用真实的模型把每个语料重放进一棵树，导出向量和词项（每个约 10 秒）：

```
STUDY_CORPUS=bench/retrieval/corpus_P1.json STUDY_OUT=dump_P1.json STUDY_MODEL=<model 目录> \
  cargo test --release study_dump -- --ignored --nocapture
```

再离线比较（旧的倒数排名融合和现在的分数融合，各按一种说法和多种说法）：

```
python bench/retrieval/compare.py dump_P*.json
```

`study_eval` 用产品里真实的搜索代码在同一批语料上跑一遍（`STUDY_MULTI=1` 带上全部说法），用来确认离线重放和真实代码一致。`study_writes` 量写入耗时。

## 指标

按「调用方实际看到的」算：命中的节点本身，或者汇总命中带出来的子节点里有答案，都算找到。`@1`、`@3`、`@5` 是答案出现在前几条的比例，`strict` 只算命中节点本身。`abstain_ok` 是库里没有答案的问题里，正确标成「没有强匹配」的比例。

## 注意

- 样本是 8 个人的约 600 道有答案的问题，差一两个百分点是噪声。
- 语料是模拟的：记忆和问题由模型按各自人设写成，问法比真人规整。结论里「大幅领先」才可信，「略好」不可信。
